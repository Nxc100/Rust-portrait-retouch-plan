## 2. 首次运行暴露的问题：身体皮肤遮罩把婚纱当成皮肤
- 身体遮罩 = MODNet 人像 alpha ∧ 严格肤色规则（YCbCr + 饱和度）。米色缎面、金饰、粉色团扇的颜色都落在肤色规则内，
  人像 alpha 又包含整件衣服 → 身体区域 2846×4485，"疤痕修复"在裙子上找到 364 处"瑕疵"并填平，刺绣被抹糊，
  修图 14.8 s；差异块 1906 个，遍布整条裙子（首版 `change_locations.png`）。
- 第一张样张没暴露这个问题，只因为那件礼服是黑色的。

## 3. 修复：语义皮肤分割门控（`face/skinseg.rs`）
- 模型：ModelScope `iic/cv_unet_skin-retouching` 中的皮肤分割 TF 图 `tf_graph.pb`（Apache-2.0，与 AI 瑕疵模型同一仓库），
  用 tf2onnx 转成 `models/skin_seg.onnx`（102 MB，opset 17，含 If / Loop 控制流）。输入 `[H,W,3]` float RGB 0..255（长边 800），
  输出 `[H,W]` uint8（255 = 皮肤）。图内先在 192×192 上做人体检测，再对人物包围盒的 448×448 裁块做粗 / 精两级分割。
  onnxruntime 与 TF 输出最大差 1 级、二值化零差异；CPU 0.16–0.35 s。详见 `doc/analysis/abpn.md` §7。
- 备选：Kazuhito00/Skin-Clothes-Hair-Segmentation-using-SMP 的 DeepLabV3+（MIT，18 MB，`models/skin_seg_lite.onnx`，
  `scripts/fetch_models.py --only skinseg-lite`，无需 TensorFlow），512×512 三类分割，同样能把米色婚纱归为衣物，但边界更粗。
  封装按输入张量的秩自动识别两种模型；引擎优先加载 `skin_seg.onnx`，不存在时才用 `skin_seg_lite.onnx`，
  `--skinseg-model` 可显式指定，横幅会显示实际加载的是哪一个（如 `+skinseg(skin_seg.onnx)`）。
- 用法：概率图缩到半分辨率 → 轻微高斯扩张（σ = 0.8% 短边）→ 软阈值 `(p − 0.15)/0.25` → 与"抠图 ∧ 肤色规则"相乘，
  再做形态学清理；脸部仍由 BiSeNet 解析决定。模型缺失或 `--no-skinseg` 时退化为原逻辑。
- 结果：身体区域 872×1266，疤痕修复 1 处，修图 3.8–4.0 s（皮肤分割 0.32 s、AI 瑕疵 1.1 s）；差异块 137 个，
  全部落在脸、颈、胸口、手臂和双手（`change_locations.png`、`preview_skin_body.png`）。裙子、团扇、金饰逐位不变。
- 回归：海边样张的输出与门控前差异 < 0.01/255（1/4 分辨率上 106 个像素 > 6/255），疤痕修复、暗斑祛除结果不变；golden 已更新。

## 6. 与像素蛋糕「奶油肌」导出图的对比与优化

### 6.1 像素蛋糕对这张图多做了一步：把文件里的 Camera Raw 设置又应用了一次
海边样张的导出图只有皮肤被改动；X04 的导出图却整幅都变了，背景墙、礼服、金饰、地毯都在内。原因在原图的 XMP 里：
X04 是 Lightroom 导出的，带有 `crs:HasSettings="True"`、`crs:AlreadyApplied="True"` 和一整套冲印参数：
色温 4550、色调 +1、高光 −44、阴影 +3、黑色 −14、纹理 +7、清晰度 +7、自然饱和度 +13；
HSL 橙色色相 −6 / 饱和度 −20 / 明亮度 +9，红色明亮度 −20；校准蓝色饱和度 +25；锐化 40；以及 Adobe Color 配置文件。
`AlreadyApplied` 表示这些调整已经在像素里了，像素蛋糕却没有理会，又应用了一次。导出图的全局变化与这些参数一一对应：

| 现象（导出 − 原图） | 对应的设置 |
|---|---|
| 奶油色礼服 / 拖尾 L −1.4~−1.8、b −1.0~−1.9；大尺度（32–128 px）上高光的对比被压到 0.94–0.96 | 高光 −44 |
| 肤色色相 −3~−4°（海边样张 +0.4~+1.2°），肤色彩度下降、变淡偏粉 | 橙色色相 −6、饱和度 −20 |
| 背景墙 a +1.0~+1.75，低饱和的暖色反而更饱和 | 自然饱和度 +13，加上橙色色相往红偏 |
| 中等反差纹理（1–16 px）+4~+9%，强边缘不变 | 纹理 +7、清晰度 +7 |
| 暗部偏暖偏红 | 黑色 −14 |

海边样张（Capture One 导出，没有 crs 设置）没有这层变化。另外，像素蛋糕还把 X04 的影棚墙面降了噪（高频标准差 0.94–1.26 → 0.10）
并去掉了墙上的小斑点；海边的天空没有被处理。这是随场景而定的"背景清理"，本项目没有复现（§6.5）。

### 6.2 实现：`color::develop`（像素蛋糕兼容的冲印再应用）
- **读取**：解析 JPEG APP1 中的标准 XMP 与扩展 XMP（按偏移拼接；其他格式直接搜索 XMP 包），支持属性和元素两种写法，
  跳过 `crs:Look` 内部的配置文件参数。只有 `HasSettings="True"` 时才生效。
- **颜色模型**：包括色调（高光 / 阴影 / 白色 / 黑色）、暗部偏色、HSL 色相与饱和度、自然饱和度（保护肤色）、饱和度和色温。
  常数由 `tools/develop_fit.py` 在 X04 上拟合，样本为非皮肤区 6 万个点加新娘皮肤（皮肤目标 = 导出图 − 海边样张测得的"只修图"偏移）。
  HSL 饱和度的作用强度随 HSV 饱和度变化，在 s ≈ 0.32 时最大：肤色被降饱和最多，低饱和的墙面和高饱和的金饰几乎不受影响。
  模型烘焙成 65³ 3D LUT，作用在**保边基底**上（导向滤波，半径 16 px，eps 0.03²），细节原样加回，类似 ACR 高光 / 阴影的局部色调映射。
  如果逐像素套用曲线，L 55–75 的细纹理会被压掉约 5%。
- **纹理 / 清晰度**：在线性光下对 L* 做带通增强（σ 1–20 px @ 5472 长边），增益为 0.0055 × (纹理 + 清晰度)，
  只作用于中等反差的细节；按比例缩放 RGB，不改变色相。
- **没有模拟**：HSL 明亮度（在 X04 上没有可测的效果）、校准、参数曲线、去朦胧、锐化、降噪、局部调整。
  横幅会逐项列出。曝光与对比度按常见公式实现，但没有样张验证。
- **开关**：奶油肌预设默认开启（`embedded_develop: true`）；`--no-embedded-develop` 关闭（按文件像素原样修图），
  其他模式可用 `--embedded-develop` 开启。库接口为 `DevelopSettings::from_path` / `apply_rgb8`，在人脸检测之前调用。20 MP 耗时 1.0 s。
- **精度**（只做冲印，非皮肤区 σ2 颜色，与导出图的加权 RMS ΔE）：不做 3.57，本项目 3.04。16³ LUT 直接拟合答案的上限是 2.37。

| 新郎头发 L / sd | 20.2 / 14.5 | 19.1 / 16.4 | 19.1 / 14.9 |

### 6.3 同时发现并修正的通用问题（两张样张都受益，详见 `doc/test_report_cream.md` §1）
- **JPEG 编码器吃纹理**：image 0.25 的编码器在量化前做整数截断，q97 时最细一档纹理只剩 0.93–0.96。
  现在改用 jpeg-encoder，默认质量 98（与像素蛋糕导出的量化表一致），并写回原图的 ICC / EXIF。
- **侧脸尺度**：X04 新郎 yaw 62°，瞳距只有 70.7 px，按瞳距设定的频段整体偏细，大块斑驳压不下去。
  纹理 / 瑕疵尺度改用 max(瞳距, 鼻梁顶—下巴距离 / 2) = 112 px；新郎低频（斑驳）在平滑处的能量比从 0.83–0.88 降到 0.72–0.76（像素蛋糕 0.56–0.71）。
- **匀肤给高光加黄**：原来的低频色度统一把所有颜色往皮肤均值拉，这张脸很亮（中位 L 82），高光面积大，
  饱和度低的高光被拉向更黄更红（不做冲印时 L 90+ 为 a +1.1、b +1.3）。现在改为向"色度 ~ L 的回归线"压缩；
  另外新增随亮度渐增的降黄 `yellow_bright`，两张样张上像素蛋糕都是皮肤越亮、降黄越多。
- 中频衰减曲线改在对数能量上、高能量处保留少量衰减；色度匀肤加强；新增眼部局部对比。

### 6.5 尚存差异
1. **背景清理没有复现**：第一次导出把影棚墙面降噪并去掉了小斑点，海边的天空却没有处理。重新导出（§6.6）的墙面也与原图一致，
   这一步同样来自示例项目的设置。本项目不改动背景。
2. **新娘肤色仍略偏黄**：L 60–90 的 b 比像素蛋糕高 0.7–1.1，a 高 0.6–0.7；皮肤高光（L 90+）暗 1.7，
   因为冲印的高光 −44 和修图的去油光叠加了。冲印模型在这张脸上给出 b −2.5~−2.7，拟合目标是 −3.25。新郎的肤色已经吻合。
3. **小脸的五官清晰度**：像素蛋糕的眼区对比增强更强（+12–18%），新郎脸的 L 各带整体 +4~+15%，更像是锐化。本项目的纹理增强不作用于强边缘。
4. 冲印模型只在这一张图上拟合过，其他参数组合（尤其曝光、对比度、色调）没有验证；不需要时用 `--no-embedded-develop` 关闭。
5. 新娘下颌的收紧弱于像素蛋糕（jaw x 少 1.1–1.5% 瞳距）。

### 6.6 更正：重新导出后没有全局调色（批量测试之后）
用户随后用「奶油肌」重新导出了 X04（`test/示例项目_导出/04_a_原图_X04_(2).jpg`），又批量导出了 7 张原片
（其中 5 张同样带 ACR crs 设置，含曝光 +0.45 等明显的参数）。这些导出的非皮肤区都与原图一致
（平均 ΔLab ≈ 0，带通能量比 1.00）。§6.1 那张导出里的全局变化来自示例项目本身的调色设置，不是预设的行为。因此：
- 奶油肌预设的 `embedded_develop` 改为 false。`color::develop` 保留为可选功能（`--embedded-develop`），
  用于复现"项目里开了读取 XMP 调色"的像素蛋糕导出；
- 以重新导出的 X04 为参考：新郎 / 新娘的中频偏差 −0.07 / −0.06，肤色差 dL/da/db 在 ±0.5 以内
  （`doc/test_report_batch.md` §3 的回归对照）。

## 7. 第一轮遗留问题
1. 新娘拿团扇的那只手几乎没被皮肤分割检出（只有几个像素），因此未处理；小面积的手容易漏检。
2. 皮肤分割在人物包围盒的 448 px 裁块上工作，全身照的掩码边缘较粗，靠"抠图 ∧ 肤色规则"和导向滤波羽化收边。
3. 侧脸（yaw > 45°）时 2d106 关键点精度下降，眼周 / 鼻翼保护区位置可能偏移；本图未见问题。
4. 年龄估计（新郎 56–62 岁）明显错误，但预设只用性别。
