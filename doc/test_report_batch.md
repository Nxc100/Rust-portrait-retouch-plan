# 测试报告：批量处理（`retouch batch`）与 7 张原片的「奶油肌」对比

日期：2026-09-24。命令：

```bash
retouch batch -i test/原片 -o out/batch --preset cream --landmarks-dir out/batch/_landmarks
python tools/batch_compare.py --orig test/原片 --ref "test/像素蛋糕“奶油肌”预设产物" \
    --ours out/batch --landmarks out/batch/_landmarks --md out/batch_compare/metrics.md --json out/batch_compare/metrics.json
```

样张：7 张原片，20–30 MP，14 张脸（8 男 6 女，瞳距 39–311 px，含 yaw −53° 的侧脸和两张全身远景）。
其中 5 张是 Canon EOS R 的 Adobe Camera Raw 17.5 导出（XMP 带 crs 冲印设置），2 张是 Canon 6D II 的
Capture One 导出。参考为像素蛋糕「奶油肌」一键导出（`test/像素蛋糕“奶油肌”预设产物/`）。
回归对照：海边样张与 X04 的重新导出（`test/示例项目_导出/04_a_原图_X04_(2).jpg`），共 4 张脸。

## 1. `batch` 子命令

```
retouch batch -i <目录或文件…> -o <输出目录> [--preset cream] [-r] [--ext jpg,png] [--format jpg|png]
              [--jpeg-quality 98] [--overwrite] [--landmarks-dir DIR] [--no-report] [--dry-run]
              [其余与 apply 相同的引擎 / 参数选项]
```

| 设计 | 说明 |
|---|---|
| 一个引擎处理全部照片 | 模型只加载一次，每张处理完清空引擎缓存，内存峰值与单张相同（7 张实测峰值 5.6 GB，最大 30 MP） |
| 三段流水 | 读图线程预取下一张（解码 + EXIF 转正），主线程修图，写图线程编码落盘；读 0.2–0.5 s、写 0.5–0.8 s 与计算重叠 |
| 逐张隔离 | 解码 / 修图 / 写盘失败（含 panic）只记在该张的报告里；引擎的锁改为"中毒后照常取用"（`sync::lock`），一张 panic 不会连累后面的照片 |
| 可续跑 | 输出先写同目录临时文件 `.<name>.partial` 再改名；已存在的输出默认跳过，中断后重跑同一命令即可续跑，`--overwrite` 覆盖 |
| 安全 | 输出目录不能等于输入目录；任何输出不能落在原图上；输出目录在输入目录内时（`-r`）不会把上次的输出当输入；隐藏文件与临时文件不扫描 |
| 命名 | 输出与输入同名、扩展名换成输出格式；同目录 `a.jpg` / `a.png` 冲突时后者为 `a.png.jpg`，多个输入目录的同名文件加序号 `a_2.jpg` |
| 报告 | `batch_report.csv`（UTF-8 带 BOM，Excel 可直接打开中文路径）与 `batch_report.json`：尺寸、EXIF 方向、人脸数 / 性别 / 年龄 / 瞳距 / 侧脸角、内嵌冲印设置、各阶段耗时、状态与原因；有失败时命令以非零状态退出 |
| 方向 | 读入时按 EXIF 方向把像素转正，写回的 EXIF 方向置为 1（`photo` 模块；`apply` / `detect` / `bench` 同样受益——之前相机直出的竖拍照片检测不到人脸） |

库接口：`batch::plan`（列出任务）、`batch::run`（执行，带进度回调）、`batch::process_photo`（处理单张）、
`photo::Photo::load` / `photo::save`（读写照片与元数据）。

耗时：7 张 92 s，平均 13.2 s / 张（修图 7.5–17.4 s；逐张 `apply` 另有约 1 s 的模型加载和 1–1.5 s 的读写）。

## 2. 发现与改动

### 2.1 「奶油肌」不改非皮肤区——内嵌冲印再应用改为默认关闭
7 张新导出与 X04 的重新导出里，非皮肤区与原图几乎一致：平均 ΔLab ≈ 0（各亮度段 |Δ| ≤ 0.1，只有 1V3A3101 / 3127 的
L 60–80 段有 +0.3~+0.5），带通能量比 1.00（最细一档 0.90–1.08 是两边 JPEG 编码的差异）。5 张带 crs 设置的照片
（曝光 −0.3~+0.45、对比度、白色、色调曲线、HSL……）也没有被再应用。第一次 X04 导出里的全局调色来自那个示例项目，
不是预设的行为（`doc/test_report_x04.md` §6.6）。奶油肌预设的 `embedded_develop` 改为 false；`--embedded-develop` 仍可开启。

### 2.2 肤色：按比例向目标色拉，提亮与黄度成正比
10 张照片 16 张脸（瞳距 ≥ 60 px）的皮肤均值变化，与原肤色高度相关（`tools/skin_tone_fit.py`）：

| | a（红） | b（黄） |
|---|---|---|
| 女 | da = −0.105 (a − 3.7)，逐脸均值 R² 0.81 | db = −0.149 (b − 9.0)，R² 0.93 |
| 男 | da = −0.089 (a − 8.3)，R² 0.72 | db = −0.090 (b − 15.8)，R² 0.84 |

偏黄偏红的皮肤降得多（1V3A3101 新娘 b 20 → −1.9），本就白净的皮肤几乎不动甚至略加暖（1V3A2922 新娘 b 4.6 → +0.6）。
原来的固定偏移做不到这一点。提亮量与原图黄度成正比（每单位 b 约 +0.035 L），在 RGB 里降黄会抬高亮度；
加入这一项后，逐脸的 dL 残差减半。`cream.rs` 第 5 步改为：低频色度（σ = 0.03 瞳距）向目标色拉
（`pull_a / target_a / pull_b / target_b`），外加 `lift_per_b` 与随亮度变化的 b 偏移。常数由逐像素最小二乘拟合
（女 / 男各 24000 个样本）。

### 2.3 纹身被当作斑点祛除（缺陷修复）
IMG_5785 与 IMG_5770 的新郎颈部有纹身，笔画的转角、端点和断续的细线被小斑检测一段段"祛除"
（`out/batch_compare/tattoo_*.png`）。只靠形状规则拦不住：单看每一段都是紧凑的暗块。做了三层修正：
1. **线状结构否决**（`blemish.rs`）：从峰值出发、在 max(0.3·峰值, 阈值) 以上连通生长，能延伸到 4r 之外的峰属于一条暗线。
   探测用不按可处理区裁剪的原始响应，因为笔画可能只有一小段落在遮罩内；
2. **强暗痕群否决**：高反差候选若在 2.5r–6r 的环内还有其他强暗痕（占环面积 ≥ 6%），视为笔画 / 发丝 / 首饰群。
   脸上只对峰值 ≥ 3（约 9 L）的候选生效，痘印 / 斑簇不受影响；身体在粗分辨率上检测，细线的反差被抹淡，门槛降到 1.5；
3. **语义皮肤门控**：身体区域的瑕疵 / 疤痕检测只在皮肤分割判为皮肤的像素上进行。墨迹的中位皮肤概率只有 0.36，
   周围皮肤是 0.996；几个像素的斑点低于模型的 800 px 分辨率，仍判为皮肤。`SkinMasks` 新增 `skin_prob` 字段携带该图。

纹身笔画中失去一半以上反差的像素：IMG_5785 11.5% → 0.5%（像素蛋糕 1.3%），IMG_5770 2.5% → 0。
顺带修掉的误修复还有：1V3A3150 手指关节的褶纹、1V3A2922 花束的花瓣纹理。海边样张的手臂疤痕照常修复，
身体祛斑量不变（|Δ| > 25 的像素数相同）。

### 2.4 瘦脸强度
重新检测输出图的关键点，比较 4 个高度的脸宽变化：像素蛋糕 女 −2.9~−3.2%、男 −0.8~−1.2%，本项目原为女 −2.4~−2.5%、男 −0.3~−0.6%。
预设改为：女 `thin_face` 0.12 → 0.15、`face_narrow` 0.025 → 0.030；男 `thin_face` 0.10 → 0.16、`chin_lift` 0.05 → 0.12、
`face_narrow` 0.004 → 0.007。之后女 −2.7~−2.8%，男 −0.6~−1.0%；鼻尖—下巴高度 女 −2.4%（像素蛋糕 −2.5%），男 −0.4%（−0.5%）。

### 2.5 小脸的纹理
瞳距 39–96 px 的 4 张脸上，像素蛋糕同样压像素级颗粒，而本项目把细颗粒 / 中频的分界下限定在 1 px，
这一档全算作细颗粒、只轻压（中频偏差 +0.10~+0.20）。下限改为 0.5 px 后，中频偏差为 −0.05~−0.07；瞳距 ≥ 200 px 的脸不受影响。

### 2.6 眼袋与泪沟
像素蛋糕把泪沟 / 眼袋压平，本项目的眼部局部对比椭圆却把泪沟的褶线也锐化了（1V3A3101 新娘、1V3A3127 新郎）。
椭圆短轴的余量从 0.10 改为 0.04 瞳距（只留睫毛），眼下额外平滑 女 0.30 → 0.40、男 0.15 → 0.35。

### 2.7 其他
- 纹理 / 色度微调：男 `fine_smooth` 0.10 → 0.05（大脸男性的细颗粒本项目压得多），女 0.22 → 0.26；
  `chroma_smooth` 女 0.36 → 0.33、男 0.29 → 0.27（色度带通比平均低 0.05）。
- JPEG 输出改用标准霍夫曼表：jpeg-encoder 的优化表在退化的符号分布上（如 16×16 纯色）会被 zune-jpeg 解成错误颜色。

## 5. 尚存差异

1. 像素蛋糕会压掉额头上的闪粉 / 亮片高光（IMG_5770 新娘），本项目只祛暗斑 / 红斑，不动亮斑。
2. 像素蛋糕的下巴更尖（V 形），本项目的收窄更均匀；女性下半脸宽度仍少约 0.3%。
3. 个别脸与像素蛋糕的取舍不同：1V3A2954 新郎，像素蛋糕压细颗粒更多（0.85，本项目 0.96）；1V3A3127 新郎脸颊的一颗痣，
   像素蛋糕保留、本项目去除；IMG_5770 新娘（瞳距 74 px）的细颗粒 0.73 对 0.88。
4. 肤色目标色只在 10 张东亚人像上拟合过，其他肤色没有验证；需要时可调整 `pull_*` / `target_*`，或把 `pull_*` 设为 0。
5. 批处理逐张串行（每张内部已多线程）。并行处理多张需要成倍的内存（每张 4–6 GB），收益有限，没有做。
